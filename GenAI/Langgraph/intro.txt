# What is Agentic AI:
- Agentic AI is a type of AI that can take up a task or goal from a user and work toward completing it on its own, with minimal human guidance. 

# Workflow: 
- Goal
- Plan
- Execution

## Key Characteristics:
- Autonomous
- Goal Oriented
- Planning
- Reasoning
- Adaptability
- Context Awareness

# Autonomous:
- Autonomy refers to the AI system ability to make decisions and take actions on its own to achieve a given goal, without needing step by step human instructions.
- It's proactive
- Autonomy in multiple facets
- Autonomy can be controlled
- Autonomy can be dangerous

# Goal Oriented:
- Goal Oriented means that the AI system operates with a persistent objective in mind and continuously directs its actions to achieve that objective, rather than just responding to isolated prompts.
- Acts as a compass for Autonomy
- Goals can come with constraints
- Goals are stored in core Memory
- This can be altered

# Planning:
- Planning is the agent ability to break down a high-level goal into a structured sequence of actions or subgoals and decide the best path to achieve the desired outcome.
- Generating multiple candidate plans
- Evaluate each plan (Efficiency, Tool Availability, Cost, Risk, Alignment)
- Best plan with help of: (Human in the loop, Pre-programmed policy)

# Reasoning:
- Reasoning is the cognitive process through which an agentic ai system interprets information, draw conclusions, and make decisions - both while planning ahead and while executing actions in real time.

- Reasoning during planning:
    - goal decomposition
    - tool selection
    - resource estimation
    
- Resoning during execution:
    - decision making
    - human in the loop handling
    - error handling

# Adaptability:
- Adaptability is the agent ability to modify it's plan, strategies or actions in response to unexpected conditions - all while staying aligned with the goal.

# Context Awareness:
- Context Awareness is the agent ability to understand, retain, and utilize relevant information from the ongoing task, past interactions, user preferences, and environmental cues to make better decisions throughout a multi step process.
- Type of context (original goal, progress till now + interaction history, environmental state, tool response, user specific preferences, policy or guardrails)
- Context Awareness is implemented through Memory
- short term Memory
- long term Memory


## Components:
- Brain (goal interpretation, planning, reasoning, tool selection, communication)
- Orchestrator (task sequencing, conditional routing, retry logic, looping & iteration, delegation)
- Tools (external actions, knowledge base access)
- Memory (short term memory, long term memory, state tracking)
- Supervisor (approval requests, guardrails enforcement, edge case escalation)

## LangGraph:
- LangGraph is an orchestration framework that enables you to build stateful, multi-step and event-driven workflows using large language models. it is ideal for designing both single agent and multi agent agentic ai applications. 
- Think of LangGraph as a flowchart engine for LLMs - you define the steps, how they are connected and the logic that governs the transitions, LangGraph takes care of state management, conditional branching, looping, pausing/resuming and fault recovery - features essential for building robust, production grade AI systems.

# When to Use What
- Use LangChain when you are building simple, linear workflows - like a prompt chain, summarizer or a basic retrieval system.
- Use LangGraph when your use case involves complex, non-linear workflows that need: conditional paths, loops, human in the loop steps, multi-agent coordination, asynchronous or event driven Execution.

# Should we still use LangChain:
- LangGraph is built on top of LangChain.
- Still use LangChain components like: ChatOpenAI, PromptTemplate, Retrievers, DocumentLoaders, Tools
- LangGraph handles workflow orchestration, while LangChain provides the building blocks for each step in that workflow.

# What is LangGraph:
- LangGraph is an orchestration framework for building intelligent, stateful and multi-step LLM workflows.
- It enables advanced features like parallelism, loops, branching, memory and resumability - making it ideal for agentic and production grade AI applications.
- It models logic as a graph of node and edges instead of linear chain.

# LLM Workflows:

1. LLM Workflows are a step by step process using which we can build complex LLM applications.
2. Each step in a workflow performs a distinct task - such as prompting, reasoning, tool calling, memory access or decision making.
3. Workflows can be linear, parallel, branched or looped, allowing for complex behaviours like retries, multi-agent communication, or tool-augmented reasoning.
4. Common Workflow: Prompt Chaining, Routing, Parallelization, Orchestrator workers, Evaluator Optimizer.

# Graphs, Nodes and Edges:

## Graphs:
- A graph is the complete workflow or execution pipeline.

Think of it as:
- the overall AI agent/application structure
- defining what steps exist and how control moves between them

## Nodes:
- Nodes are the individual processing steps in the workflow.

Each node usually:
- receives the current state
- performs some logic
- returns updated state

Examples of nodes:
- LLM call
- tool execution
- retrieval step
- validation step
- memory update

## Edges
- Edges define how execution moves between nodes. They connect nodes together.

Types:
- Normal edge → always go to next node
- Conditional edge → route based on logic/output


# State:
- In LangGraph, state is the shared memory that flows through workflow - it holds all the data being passed between nodes as graph runs.

# Reducers:
- Reducers in LangGraph define how updates from nodes are applied to the shared state. Each key in the state can have its own reducer, which determines whether new data replaces, merges, or adds to the existing value.

# LangGraph Execution Models:
1. graph definition: Define the workflow structure by creating nodes, edges, and the shared state schema.
2. compilation: Convert the graph definition into an executable runtime by validating nodes, edges, and reducers.
3. invocation: Start graph execution by providing the initial input state and activating the entry node.
4. super step begin: LangGraph begins a synchronized execution cycle where all active nodes run in parallel.
5. message passing and node activation: Nodes return state updates/messages, reducers merge them into the global state, and downstream nodes become active for the next super step.
6. halting condition: Execution stops when there are no active nodes or pending messages left in the graph.

# Sequential Workflow in LangGraph:
- Sequential Workflow in LangGraph is a workflow design pattern where tasks are executed step-by-step in a fixed order. Each node in the graph performs a specific operation, and the output of one node becomes the input for the next node. This approach is useful for building structured AI pipelines such as data processing, content generation, validation, and decision-making systems where the flow must follow a clear sequence. In LangGraph, sequential workflows help create modular, maintainable, and easy-to-debug AI applications.

# Parallel Workflow in LangGraph:
Parallel Workflow in LangGraph allows multiple tasks or nodes to run simultaneously instead of executing one after another. This workflow is useful when independent operations can be processed at the same time, improving speed and efficiency. In LangGraph, different nodes can handle separate tasks in parallel, and their outputs are later combined or processed further. This approach reduces execution time and helps optimize complex AI applications.

# Conditional Workflow in LangGraph:
Conditional Workflow in LangGraph is a workflow where the execution path changes based on specific conditions or decisions. Instead of following a fixed sequence, the workflow dynamically selects the next node according to the input, state, or output of previous steps. In LangGraph, conditional edges are used to control the flow between nodes. This allows the system to make intelligent decisions and execute different actions depending on the situation.

# Iterative Workflow in LangGraph:
Iterative Workflow in LangGraph is a workflow where a task or process is repeated multiple times until a specific condition is met. Instead of moving directly to the next step, the workflow loops through the same nodes to refine, validate, or improve the output. In LangGraph, iterative workflows are created using loops and conditional edges that allow nodes to execute repeatedly based on the current state or result.

# What is Persistence:
- Persistence in LangGraph refers to the ability to save and restore the state of a workflow over time.
- Persistence means the ability of a system to save and remember data or state information even after the program stops or restarts.
- In AI workflows and frameworks like LangGraph, persistence helps the application continue from where it left off instead of starting from the beginning every time.

# Checkpointers in Persistence:
- Checkpointers are mechanisms used to save snapshots (checkpoints) of the workflow state during execution.

    A checkpoint stores:
    - Current step of execution
    - Messages/state data
    - Intermediate results
    - Workflow progress

If the system crashes or stops, the workflow can restart from the last checkpoint instead of running everything again.

# Threads in Persistence:
- Threads are unique identifiers used to track separate conversations or workflow executions. Each thread represents an independent session.


# Benefits of Persistence:
- Short term memory
- Fault tolerance
- Human in the loop
- Time travel

    - Its job: listen for tool calls from the LLM and automatically route the requests to the correct tool, then pass the tool output back into the graph.

# Human In The Loop (HITL):

### What is HITL:
- HITL is a design approach in AI systems where a human actively participates at critical points of the AI workflow - either to supervise, approve, correct or guide the model's output.
- Think of HITL as putting a human "checkpoint" inside an AI pipeline so that important decisions are not made autonomously by the model.

### Why HITL:
- To help agentic systems.
- To add accountability.

### HITL Ensures:
- Accuracy
- Safety
- Ethical Alignment
- Better user experience
 
### Common HITL Patterns:
- Action Approval Patterns
- Output Review / Edit Patterns
- Ambiguity Clarification Patterns
- Escalation Patterns

# LLM Memory:
- A LLM at inference is just a Parameterized math function. [y = f(x)]
- Context Window: The context window is the amount of text an LLM can read and remember at one time before answering.
- In-context Learning is an emergent ability that allows an LLM to use information and patterns present in the prompt itself, in addition to its trained parametric knowledge, to generate an answer.

### Problems with Short Term Memory:
- Short Term Memory is Fragile.
- The context window problem.
- STM is thread-scoped. (loss of user continuity across conversations, learning never compounds over time, cross-thread reasoning is impossible).

### Solution:
- Information that should survive.
- It has to be selective.

## Types of Long Term Memory:
- Episodic Memory (what happened)
- Semantic Memory (what is true)
- Procedural Memory (how to do things)

## How does Long Term Memory Work?
- Creation: Is anything from what just happened worth remembering beyond this conversation.
- Storage: Where and how do we keep this memory. 
- Retrieval: Given the current situation, what should i remember right now. (Retrieval is selective, not exhaustive).
- Injection: How does memory actually influence the model. (LTM -> Search -> STM -> Context -> LLM)

## The Challenges: (LangMem, memo, supermemory)
- Deciding what is worth remembering.
- Retrieving the right memory at the right time.   
- Orchestrating the entire system.

## Context Overflow Problem:
- The context overflow problem occurs when the total amount of information sent to an LLM exceeds its maximum context window. When this happens, the model cannot consider all the information, so some content must be removed or truncated.
